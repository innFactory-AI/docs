To use companyRAG in CompanyGPT, we first need to create a document collection. Open companyRAG via [All apps](/en/company-gpt/addons/alle-apps/) using the **Knowledge** tile, or navigate directly to `https://COMPANY.company-gpt.com/companygpt/rag` (if you use a custom domain, just append `/companygpt/rag`).

## Create a Collection

In the sidebar, navigate to **Collections** and select **Create Collection**. Select **Documents** as the **Collection Type**, enter a name, a description, and choose the visibility.

The **technical name** will be relevant for the prompt later.

![sammlung-erstellen](sammlung-erstellen.png)

For visibility, you can choose between **Private** and **Public**. **Public** collections are available to all users; **private** collections are only accessible to the owner, but can be shared with others at any time. Later, a collection can be shared with people and groups via **Share Collection**, or with everyone using the **Share with everyone** switch.

### Advanced Settings

In the advanced settings you can adjust – depending on the environment – the embedding model, search language, chunking strategy, chunk size, and overlap. The default values can be left as-is for most use cases.

:::tip
The search language should ideally match the language of the documents in the collection. Both semantic and full-text search are performed, and full-text search works better with the correct language setting.
:::

![erweiterte-einstellungen](erweiterte-einstellungen.png)

## Index Documents

Once the collection is created, you can add documents.

### Manual Upload

![manualler-upload](manualler-upload.png)

Under **Upload**, simply select the collection and the documents and upload them. Manual uploads have no file-level permissions and no additional metadata beyond the file name.

### SharePoint, Nextcloud and other sources

![quellen](quellen.png)

Under **Sources**, a new connection can be created – besides SharePoint also to Nextcloud, Google Drive, GitHub, WebDAV, FTP or via web crawl. Below we show the path for SharePoint.

:::tip
If no integration has been connected yet, first sign in to **Microsoft SharePoint** under **Integrations** via **Connect**.

![integrationen](integrationen.png)
:::

Under **Sources**, the **Connect SharePoint** button in the **SharePoint** tab then starts the selection. Under **Content to Sync** we choose whether files, Pages & News, or both are synchronized. Then we choose the site or team, the library, and the SharePoint folder to use — all subfolders of the selected folder are always included.

![sharepoint-browser](sharepoint-browser.png)

Once the desired folder is selected, choose the collection and click **Select This Folder**.

![sharepoint-folder](sharepoint-folder.png)

Then select the file types to index and click **Connect SharePoint**. The first synchronization then starts automatically, and future changes in the folder are picked up on their own.

![sharepoint-filetypes](sharepoint-filetypes.png)

:::note
Documents indexed via SharePoint have document-level permissions. When querying through CompanyGPT, permissions are always checked regardless of how the collection is shared.
:::

## CompanyGPT Agent

Via the [MCP Server](/en/company-gpt/integrationen/mcp-server/) `ai-search`, the RAG service can be connected to CompanyGPT to search indexed documents across all collections available to the user
(see [Similarity Search](/en/prompt-engineering/prompt-techniken/rag/)).

### Agent Prompt

To use the RAG search, an [agent](/en/company-gpt/agenten/) must be created. It requires the MCP Server `ai-search` with the tools `search_content`, `find_content_by_metadata`, and `find_content_by_source` enabled.

![mcp-server](mcp-server.png)

If the folder contains tables (CSV, Excel, Parquet), also enable `execute_sql` and `describe_table`. New collections have the option [Tabular files as datasets](/en/company-gpt/addons/companyrag/sammlungen/#tabular-files-as-datasets) switched on: search then only returns a sample from such files, and the agent queries the actual values with the SQL tools.

A smaller AI model is usually sufficient for the agent, e.g. **Claude Haiku** or **Gemini Flash**, but any other model works too.
